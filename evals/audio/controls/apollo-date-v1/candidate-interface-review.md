## Результат

Все 22 имеют извлечённый WAV и остаются `pending_audio_adjudication`; общий статус `pending`, `production_ready=false`. Ни одно расхождение само по себе не доказывает дефект TTS.

В исходных segments действительно есть четыре интервала нулевой длины: indices 622 (`5`), 658 (`2`), 693 (`2`), 797 (`8`). В данном результате их числовые формы не совпадают с transcript, поэтому эти участки уже стали uncertainty и получили окна по соседним anchors. Ранее описанный риск нулевых таймкодов относится к совпавшему тексту; ложного принятия этих четырёх segments в текущем результате не произошло.

## Требования к payload перед actual-audio вызовом

1. **Шесть recognition_uncertainty не самодостаточны для согласованного prompt.** У них отсутствуют expected tokens/context и script selectors. Не превращать отсутствие reference в пустую ожидаемую речь и не пропускать эти cases. Для каждого восстановить точную source reference/селекторы по полному alignment с сохранённой неопределённостью при неоднозначности. Сравнение только двух ASR-представлений не проверяет произнесённое против сценария.
2. Для 16 script discrepancies брать `expected_words` точной подстрокой source по selectors, а не реконструировать текст простым join нормализованных токенов. Передавать соседнюю короткую фразу с единицами и anchors: для `94 с половиной` нужны «часа после старта», для `двадцать` — «часов». Полный raw/context остаётся в persisted report.
3. `asr_transcript_excerpt` брать дословно из `Recognition.text` по char spans; `asr_segment_excerpts` — дословные исходные segments с их исходными start/end. Не выдавать normalized `0 2` за буквальный raw segment текст: в этом чтении для таблицы показаны segment **tokens**, а raw segments берутся из receipt/recognition.
4. Для каждого WAV передавать фактический clip SHA-256, measured duration и master start. `heard_spans` обязаны быть относительны этому WAV. ASR range не является доказательством точной слышимой границы.
5. Кандидаты 11 и 17 имеют одно и то же окно 263.26–267.38 и одинаковый WAV: это одна аудиопроверка с двумя основаниями, но результат нужен для каждого case ID. Остальные перекрытия также не являются независимыми подтверждениями.
6. Имена не исправлять автоматически по fuzzy similarity. Особенно `Хейз/Хейс` может отражать орфографию ASR/произношение; при отсутствии достаточной основы для вердикта использовать `pronunciation_reference_unresolved`. Число-слово допустимо только при совпадении значения, единиц и scope.
