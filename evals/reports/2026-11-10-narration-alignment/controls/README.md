# Контроль редактора: объяснение, повтор и голос

Четыре неизменённых сохранённых текста, семь приватных проверок фрагментов. Текст подаётся целиком: обрезка сцены могла бы сама лишить пояснение контекста. В production-примеры эти контроли не добавляются.

| ID | Сохранённый материал | Что проверяется |
| --- | --- | --- |
| 01 | Полный черновик Сноу из ending-and-first-listen | Две фразы после уже понятного ответа девочки; нужная гипотеза до подозрения; образ и обычный итог |
| 02 | Полная первая перепись дождя из того же прогона | Повтор различия свечения; нужное объяснение жизнеспособности и часовой выдержки |
| 03 | Revised telling №1 из прежнего pinned craft reference | Сухая шутка с неверной тетрадью и полезное объяснение ошибки осветителя |
| 04 | Revised telling №2 из того же образца | Юмор через два пирога и точная билетная выручка без лишнего финансового предупреждения |

[cases.json](cases.json) закрепляет исходный путь, SHA, точный диапазон для фрагмента образца и файл текста в `inputs/`. Ни одного слова сохранённых текстов не заменено. Для 01 и 02 сохранены также аудитория, жанр и временные рамки реального reader-запроса.

[expectations.json](expectations.json) — только для оценивающего. В нём точные цитаты, адреса и ожидаемое решение. Они не входят в модельные запросы. Дополнительные обоснованные замечания допустимы; правильность трёх технических исправлений не компенсирует пропуск адресного сокращения в 01.

## Готовые запросы для централизованного исполнения

[prepared.json](prepared.json) закрепляет четыре файла `requests/01.json` … `04.json`, их SHA, reader prompt `5fa00d50…`, схему `/12` и `endpoint_called=false`. Все запросы собраны штатным `preview_request`, с production-профилем `gpt-6.1-terra`. В model-facing payload только `output_language`, `audience`, `format`, `genre`, `script`, `duration_context`; ни источников отбора, ни ожиданий, ни сравнений с другим вариантом там нет.

Отправку, подсчёт токенов провайдером и расходы ведёт центральный запуск. Здесь оплаченных вызовов нет. Для единственного повторного чтения **того же входа первого контроля** отдельно подготовлен `tmp/commentary-alignment/snow-same-input-reader-request.json`: от первого оплаченного запроса изменены только инструкция и схема. Для проверки всех четырёх материалов использовать закреплённые `requests/` по отдельности и оценивать результаты по приватным ожиданиям.

Проверять точные исполнимые адреса сокращения и его обязательность; сравнение должно опираться на то, что уже стало понятно до комментария. На положительных образцах проверять, что редактор сохраняет юмор и голос без требования новой информации, объяснения шутки или нового финального вывода. Эти ожидания не являются инструкцией для модели.
