# Сначала расшифровка, затем сравнение: результат

**Частичный успех.** На контрольной паре женского/среднего рода получены правильные
решения без изменения «услышанных» слов. Числовая запись даты тоже обработана
правильно. Но текстовый сравниватель снова принял различие написаний «потому» /
«по тому» за основание для различия произносимых форм. Проверка записи в целом
не квалифицирована; production, полный выпуск и автоматическое исправление не менялись.

## Что проверяли

Те же три окна Сноу, тот же PCM, `gpt-realtime-2.1`, medium, максимум 4096 выходных
токенов. Сначала три отдельных запроса только со звуком и заданием расшифровать.
Сценарий, ASR и правильные ответы в эти запросы не попали. Затем четыре независимых
текстовых сравнения без аудио. Обе версии W4 получили одну и ту же сохранённую
расшифровку; различается только `expected_words`.

В контроле даты reference заменён с «первое» на «1» перед «сентября»: так проверяется
эквивалентность записи после удаления ASR из входа. Изменение явно сохранено в
manifest; blind-запрос его не получает. Подтверждение пользователя хранится отдельно
в `previous-human-confirmation.json`, не входит ни в один запрос.

| Контроль | Расшифровка целевых слов | Сравнение | Оценка |
|---|---|---|---|
| W4, правильный reference | главная подозреваемая | matches | Правильно; совпадает с подтверждением пользователя. |
| W4, reference «главное подозреваемое» | та же расшифровка | differs; цитирует женскую форму | Правильно; прежняя подмена услышанных слов в этой паре не повторилась. |
| W3, reference «1 сентября» | первое сентября | matches | Правильно; день сохранён, различие записи не объявлено ошибкой. |
| W5, reference «по тому» | потому | differs | Неподдержанный вывод о произносимой форме: объяснение различает значения написанных слов, не их звучание. |

Все цитаты сравнивателя дословно присутствуют в сохранённых расшифровках. Для W5
акустического подтверждения пользователя нет. Сама запись не объявляется ни
ошибочной, ни проверенной: установлена проблема обоснования вердикта.

## Полные blind-ответы

**W4:** «Пока умирают сотни людей, а главная подозреваемая выглядит почти невинной.»

**W3:** «С тридцать первого августа на первое сентября холера.»

**W5:** «Знать и судить о нем можно только потому, что оно делает.»

Human confirmation относится только к «главная подозреваемая» и «первое сентября».
Остальные слова, особенно края коротких окон, этим не проверены. Например, соседние
«Пока» и «невинной» отличаются от сценария, но не получили независимого прослушивания.
Расшифровка остаётся гипотезой распознавания, а не эталоном записи.

## Вывод

Сохранение расшифровки до передачи сценария не позволяет следующей стадии менять её
под ожидаемый текст. На подтверждённой пользователем паре это помогло. Но отдельно
остаются точность распознавания и сравнение произносимых форм. Текстовое сравнение
не восстанавливает ударения и другие звуковые признаки, которых нет в его входе.

Следующая работа — определить, какие расхождения в расшифровке достаточно обоснованы
для проверки записи, а какие относятся только к её написанию. Локальная правка под
«по тому» не решит общий случай. Этот эксперимент не обосновывает автоматическую
переозвучку или надёжность на остальных фрагментах выпуска.

Это проверка нового разделения задач, а не чистый A/B одной строки: изменены
видимость материалов, поручения и контракт результата. По одной попытке на условие
нельзя оценить частоту ошибок. Прежние сохранённые ответы не перезаписаны.

## Воспроизводимость и стоимость

Оператор: `evals/operator/audio-blind-comparison/`. Здесь сохранены все текстовые
входы, инструкции, ответы, manifest, usage и hashes трасс. Полные wire/events с
PCM лежат в `tmp/audio-blind-comparison-2026-11-12/`; из отчёта удалён только base64
аудио, вместо него сохранены размер и hash.

Все четыре текстовых ответа обернули JSON в Markdown. Это нарушение формата
зафиксировано в `parse.json`: снята только внешняя оболочка, исходный ответ сохранён,
повторных запросов не было. Это диагностический оператор, не готовый продуктовый контракт.

Проверки без API подтвердили неизменность audio events, отсутствие подсказок в blind
payload, одинаковую расшифровку W4 и блокировку повторной отправки. Выполнена проверка
синтаксиса Python. Тяжёлые тесты не запускались.

**7 вызовов: 3 аудио + 4 текстовых. Оценка стоимости по usage: $0.035152**, не счёт
провайдера. Reasoning уже входит в выходные токены и отдельно не прибавлялся.

Текстовая последовательность запросов сверена с
[официальной документацией Realtime](https://developers.openai.com/api/docs/guides/realtime-conversations).
