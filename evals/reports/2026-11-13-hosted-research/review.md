# Независимое ревью hosted research adapter

13 ноября 2026. Проверены рабочие версии `backend/src/podgen/research/hosted/{contracts,provider,transport,journal,service,state,material,export}.py`, CLI и тексты адресных тестов. Backend не менялся; API и тесты рецензентом не запускались. Реальный отчёт ещё не получен, разрешение на live-вызов ожидается.

**Вывод:** два найденных дефекта исправлены в прочитанном коде. Подтверждённых незакрытых дефектов в проверенных путях нет. Это заключение о контракте и восстановлении, не оценка качества Gemini-исследования и не подтверждение живой интеграции.

## Найденные дефекты и исправления

1. **[P2, исправлено] Терялись предыдущие текстовые `model_output`.** `material.report()` выбирал только последний output: при нескольких блоках из material view выпадали предыдущий текст, annotations и ссылки. Теперь обрабатываются все текстовые content blocks всех `model_output` в исходном порядке, сохраняются native provider paths и диапазоны в собранном тексте. Разделитель между блоками явный; содержание блоков не сокращается. Такой обход соответствует [официальному CLI-примеру Google](https://aistudio.google.com/docs/deep-research). Raw response сохраняется независимо от извлечённого текста.

2. **[P2, исправлено] Обрыв записи binding блокировал следующий resume.** Раньше `binding.json` создавался непосредственно в целевом каталоге: обрыв между созданием и окончанием JSON оставлял файл, который предварительный export следующей CLI-команды не мог прочитать. Теперь `export.bind()` полностью пишет временный файл в родительском каталоге, делает flush/fsync и публикует его через `os.link` с create-if-absent. Чужой binding не заменяется; временный файл до публикации не делает export-каталог непустым. JSON assets также публикуются через временный файл и replace. Новая логика прочитана; crash-проверка рецензентом не запускалась.

## Авторизация и восстановление

- `prepare` сохраняет полный assignment, английскую инструкцию, профиль, подготовленный request и его blob/hash. Изменённый config под прежним run отклоняется. `manifest()` проверяет hash и bytes request перед действием.
- Approval хранит actor/time, exact request hash и согласие на переменную стоимость одного исследования. Это не обещание жёсткого USD-потолка. Без approval `advance()` не вызывает провайдера.
- Submit intent сохраняется до POST. Если intent уже есть, а надёжного ответа с job ID нет, повторный resume возвращает unknown/rejected и не отправляет новый POST. Неопределённый исход не объявляется успешным.
- Полный receipt сохраняется до `job` и обработки отчёта. `latest()` восстанавливает известный ID из receipts; сбой после сохранения receipt не требует нового исследования. При известном активном job дальнейшее действие — GET того же ID.
- Неуспешный GET не стирает последний известный job. Смена ID в успешном snapshot отклоняется. Advisory lock сериализует действия одного project/run; journal использует project ACL, immutable runtime records и проверяемые blob bindings.
- `completed` без пригодного отчёта остаётся processing error с сохранённым receipt. Failed/incomplete/cancelled/requires_action/requires_continuation не выдаются за готовый отчёт. Reprocess сохранённого completed receipt выполняется без сети.

## Полнота материала и граница evidence

Отдельно сохраняются raw response, полный текст отчёта и reported sources. Каждый извлечённый текстовый блок привязан к native path и диапазону в report; provider annotations сохраняются дословно. Их byte offsets не смешиваются с символьными диапазонами собранного текста: [API Google определяет citation offsets в байтах](https://aistudio.google.com/api-reference/interactions-api).

URLs из annotations и текста имеют `evidence_status=reported_only`; список явно не называется полным журналом чтений провайдера. Adapter не создаёт фиктивные EvidenceSpan и не заявляет, что Podgen получил документ по ссылке. Последующий ingestion и точные привязки источников ещё должны подтвердить собственные состояния отдельно.

## Что ещё предстоит проверить

Реальный submit/poll, форма фактического ответа, полнота его импорта, usage и доступность сообщённых источников пока не проверены этим ревью. После получения отчёта требуется независимое содержательное чтение по `review-criteria.md`. Пригодность передачи планировщику проверяется затем на самом плане и отдельной рецензии; adapter сам по себе этого не доказывает. Утверждённый `request.txt` не расширялся.
