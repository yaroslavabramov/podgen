# Редакционный вход: offline-проверка изменения

Новых сценариев и вызовов OpenAI здесь нет, включая endpoint подсчёта токенов. Подготовлены смысловые входы GPS и Сноу, 11 текущих английских промптов и просмотр фактической сборки. Полные первичные материалы сохранены; сменился состав задания каждой роли.

## Полный GPS-запрос до и после

- **До:** [все видимые поля JSON](gps-author-before.visible.json); полный HTML можно собрать командой ниже. Это фактический архивный own-plan запрос автора, для которого API сообщил 153 409 входных токенов. В нём целые документы, технические пути, кандидат, положительный отзыв и противоречивое предложение построить собственный план.
- **После:** [читаемый запрос целиком](gps-author-after.html), [все видимые поля JSON](gps-author-after.visible.json). Собран обычным offline CLI из нового shared. Пример собственного плана [написан специально по новым карточкам](fixtures/gps-conditional-own-plan.json), **его принятие условно предполагается только для показа авторского входа**. Готовый fixed-план и старый сгенерированный план для этого примера не загружались. Это не результат генерации, не реальный `accept` и не оценка нового сценария.

HTML раскрывает JSON внутри входного сообщения для чтения, сохраняя все значения. Строки и документы не сокращены. JSON рядом сохраняет точную видимую структуру с исходной строкой сообщения. Транспортные metadata в эти три видимые части не входят.

| Видимая часть | Старый фактический запрос, байт | Новый условный пример, байт |
| --- | ---: | ---: |
| Инструкции | 5 289 | 2 235 |
| Вход | 611 723 | 29 429 |
| Строгая схема ответа | 710 | 710 |
| Всего | 617 722 | 32 374 |

Это длина компактного UTF-8 JSON каждого компонента, одинаковым способом для обоих запросов. Новый пример меньше примерно в 19 раз по этой метрике; это не отношение токенов и не предсказание качества. [Метрики и контрольная сумма исходного архивного запроса](metrics.json). Координатор независимо измерил **именно опубликованные JSON** локальным `o200k_base`: **153 429 → 4 784 токена**. Учтены инструкции, текст всех content и компактный JSON строгой схемы, без провайдерского framing. Исторический API-замер — 153 409; локальное число его не заменяет. Содержание материала и условный план после измерения не менялись; повторная сборка дала побайтно тот же опубликованный видимый JSON.

В новом авторском задании остались измерение по сигналу, общая ошибка часов, совместная оценка места и времени, условные маяки, геометрия, числовой масштаб и остаточные ошибки. Сохранились функции Нины и Ильи, язык, аудитория и границы 780–1080 секунд при цели 900. Учебная формула и пример атрибутированы как редакторские объяснения. Автор получает решения открытия, актов, переходов, финала и выбранные утверждения с контекстом и пределами. Исходных выдержек, путей, хешей, положительной рецензии и задания снова планировать во входе нет.

## Что подготовлено и проверено

[Входы и их смысловые ограничения](../../editorial-inputs/v1/README.md): GPS — 9 карточек и 3 519 знаков выдержек; Сноу — 16 карточек и 17 578 знаков. Первая неудачная упаковка содержала соответственно 11 912 и 59 611 знаков повторных больших выдержек и заменена ручным отбором. Повтор короткой GPS-дефиниции оправдан связанными выводами; сервер объединяет одинаковые диапазоны. У Сноу одинаковых текстов выдержек нет.

Сноу сохраняет различие 89/83 по регистрации и наступлению смерти, неопределённую дату приобретения дополнительных свидетельств, границы таблицы, спад до закрытия, позднюю физическую проверку, зависимость свидетельств, спорный диагноз и временные возражения. Оба направления клинического спора оставлены. Маркеры экстрактора на двух границах страниц исключены выбором отдельных точных диапазонов; исходник не переписан. Формула слайда NASA 38 не объявлена цитатой текстового извлечения.

Локальный импорт обоих shared через обычный CLI прошёл серверную проверку происхождения и точных диапазонов. Собраны GPS `plan` (33 285 байт), GPS `draft` (32 374 байта), GPS `plan-review` (53 094 байта) и Сноу `plan` (46 171 байт). У каждого `endpoint_called=false`. Проверки ресурсов промптов: **23 passed**, включая проверки с локальным хранилищем. Утилиты offline-просмотра: **5 passed**; дополнительно повторены обычные CLI-сборки GPS `plan`, `draft` и `plan-review` с новым форматом состояния и удалением API-ключей из дочернего окружения. Это проверка данных и сборки, а не исполнения редакционных решений моделью. Раздельный fixed-вход связан с каноническим digest соответствующего shared; own-сборка его не загружала.

Текущие промпты дают каждой роли одну задачу. Автор реализует принятую историю; редактор проверяет услышанное по реальным репликам; ремонты выбирают адрес существующего суждения и работают отдельными инструкциями. Общий текст не повторяет целую редакционную методичку. Полные отзывы остаются в хранилище, автору не передаются похвала и вывод об одобрении плана.

Однозначный `keep` теперь завершает путь точным сохранённым черновиком без нового вызова автора; `needs_material` останавливает цепочку, `revise` запускает содержательную правку. Противоречивое решение возвращает ошибку. Причина изменения видна в [старых GPS-запусках](../2026-11-05-planning/README.md): оба финала побайтно совпали с черновиками, хотя вызовы редакции состоялись и оплачивались. Новый runtime сохраняет происхождение `unchanged_draft` и `model_call=false`, не придумывая ответ модели. Это не допуск к публикации.

## Бесплатно собрать и открыть

Нужны установленный backend и локальная PostgreSQL с миграциями, как в [инструкции запуска](../../../backend/WRITING-EVALUATION.md). Передайте `PODGEN_DATABASE_URL` отдельно через окружение. Утилиты не читают `.env`; дочерние процессы получают окружение без `OPENAI_*` и `AZURE_OPENAI_*`. Файл состояния содержит только проверяемые значения UUID, путей и назначения; исполняемые команды из него не загружаются. После обновления утилит пересоздайте старый `state.json` первой командой. Следующие команды из корня проекта создают отдельное локальное назначение, импортируют полные оригиналы, проверяют выдержки и вызывают только обычный CLI `preview`; команда `run` и провайдер не используются.

```sh
PYTHONPATH=backend/src backend/.venv/bin/python \
  evals/reports/2026-11-05-editorial-inputs/tools/preview.py \
  --case gps-clock \
  --approved-plan evals/reports/2026-11-05-editorial-inputs/fixtures/gps-conditional-own-plan.json \
  --out tmp/editorial-input-preview/gps-clock

PYTHONPATH=backend/src backend/.venv/bin/python \
  evals/reports/2026-11-05-editorial-inputs/tools/preview.py \
  --case snow-pump --out tmp/editorial-input-preview/snow-pump
```

Результат содержит `plan.preview.json`, для GPS также `draft.preview.json`, отдельные `*.visible.json` и `state.json` с локальными ссылками. Для следующих стадий используйте собственные точные сохранённые результаты:

```sh
PYTHONPATH=backend/src backend/.venv/bin/python \
  evals/reports/2026-11-05-editorial-inputs/tools/preview_stage.py \
  tmp/editorial-input-preview/gps-clock/state.json \
  --stage plan-review \
  --candidate evals/reports/2026-11-05-editorial-inputs/fixtures/gps-conditional-own-plan.json \
  --out tmp/editorial-input-preview/gps-clock/plan-review.preview.json
```

| `--stage` | Дополнительные файлы |
| --- | --- |
| `plan` | Нет |
| `plan-review`, `plan-review-revised` | `--candidate` |
| `plan-revise` | `--candidate`, `--plan-review` |
| `draft` | `--approved-plan` |
| `review` | `--approved-plan`, `--draft` |
| `revise` | `--approved-plan`, `--draft`, `--feedback` |
| `plan-target-repair` | `--candidate`, `--plan-review` с действительно неразрешённым адресом |
| `anchor-repair` | `--draft`, `--feedback` с действительно неразрешённой цитатой |

Выборочный ремонт без дефекта возвращает явную ошибку. Для fixed-просмотра отдельно импортируются исходный документ плана и `fixed-plan.json`, затем передаётся `--fixed-ref`; shared остаётся тем же. Предъявлять fixed-вход как own нельзя.

Откройте готовый новый HTML обычным браузером. Старый большой HTML не хранится второй копией корпуса; при необходимости соберите его из точного JSON:

```sh
python3 evals/reports/2026-11-05-editorial-inputs/tools/render_request.py \
  evals/reports/2026-11-05-editorial-inputs/gps-author-before.visible.json \
  tmp/editorial-input-preview/gps-clock/before.html \
  --title 'GPS: старый авторский запрос' --note 'Архивный запрос, старое условие входа'
```

Для своего полного видимого JSON:

```sh
python3 evals/reports/2026-11-05-editorial-inputs/tools/render_request.py \
  tmp/editorial-input-preview/gps-clock/draft.visible.json \
  tmp/editorial-input-preview/gps-clock/draft.html \
  --title 'GPS: авторский запрос' --note 'Условный offline-пример, без вызова модели'
```

Перед будущим платным submit runtime проверяет 128 KiB видимых данных и реальный входной токенный предел 32 768. Никакие смысловые поля ради лимита не обрезаются. [Полный контракт ролей и сохранности](../../../docs/podcast-production/08-editorial-inputs.md).
