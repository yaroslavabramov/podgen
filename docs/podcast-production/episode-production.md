# Выпуск из темы

Координатор использует действующие hosted research, получение источников,
план с отдельной рецензией, автора, две независимые проверки, синтез и сборку.
Модели, инструкции и голос задаются точными сохранёнными профилями в settings.

Из корня репозитория, после восстановления рабочего подключения и загрузки
ключей провайдеров в окружение:

```sh
PODGEN_DATABASE_URL='<рабочее подключение>' backend/.venv/bin/alembic -c backend/alembic.ini upgrade head

backend/.venv/bin/python -m podgen.episode_cli \
  --reference-state tmp/hieroglyphs-production-2026-11-14/reference-state.json \
  --run-id 63f3265a-1ff4-5526-85c7-92f723f435e7 \
  start --topic 'Как расшифровали египетские иероглифы' \
  --settings tmp/hieroglyphs-production-2026-11-14/settings.json \
  --export-dir tmp/hieroglyphs-production-2026-11-14/export
```

`start` сначала проверяет и сохраняет неизменяемую конфигурацию, затем выполняет
весь путь. `prepare` выполняет только бесплатную подготовку. Для новой темы
нужен новый `run-id`; менять входы уже подготовленного запуска нельзя.

С теми же глобальными параметрами вместо `start …`:

| Команда | Результат |
|---|---|
| `status` | Один ограниченный запрос состояния; без провайдеров и записей истории. |
| `pause` | Сохранённая остановка перед следующим внешним действием. Уже полученный ответ сохраняется. |
| `resume` | Снимает остановку и продолжает сохранённые операции. |
| `run` | Продолжает, сохраняя действующую остановку. |
| `export --export-dir PATH` | Выгружает исследования, сценарии, проверки и собранный `audio/master.wav`. |

Опрос исследования выполняется раз в 15 секунд; `--step` возвращает управление,
когда нужен следующий опрос. Неопределённый исход платной отправки автоматически
не повторяется. `needs_attention` содержит точную причину остановки.

## Владение и ограничения

Родитель хранит конфигурацию, фазу, детерминированные ID дочерних операций и
ограниченный прогресс. CAS и отдельная блокировка исключают двух исполнителей.
Дочерние журналы остаются владельцами запросов, ответов, затрат и восстановления.
Проверки доступа выполняются заново перед внешним действием и чтением результата.

Дополнительные материалы используют тот же принятый план. Две реальные правки
сценария считаются суммарно, включая продолжения. Известные вопросы завершённых
рецензий объединяются в одно исследование без потери формулировок. Лимит заданий
research и бюджет аудио задаются явно; расширение лимитов не происходит само.

Аудио охватывает все реплики по порядку. Обычные реплики остаются целыми;
слишком длинные делятся по предложениям, затем словам. Сборка проверяет точное
покрытие символов и исходную версию сценария; темп не подгоняется.
Части полного рендера обрабатываются по `ffmpeg-assembly-input/1`: сохраняется
исходный decoded PCM, громкость меняется один раз после сборки мастера. При
смене версии локальной обработки сохранённый успешный HTTP-ответ можно обработать
новой ревизией без повторного TTS; прежние ошибки и PCM остаются в архиве.

`assembled` означает собранный мастер с ожидающей акустической проверкой.
`production_ready` остаётся `false`. Это не разрешение на публикацию.

## Проверка собранного звука

Новый выпуск (`prepare`/`start`) получает `audio_verification` по умолчанию: Fish `transcribe-1-pro`, $0,006 за минуту (проверено 2026-11-12), `max_repair_rounds=2`; ключ `FISH_API_KEY` проверяется вместе с остальными до первой оплаты. Выпуски без настройки и уже сохранённые конфигурации озвучиваются как раньше (`audio-render/1`).

С настройкой озвучка идёт как `audio-render/2`: на часть заложено `1 + max_repair_rounds` попыток синтеза. Первый собранный мастер распознаётся целиком один раз (`audio-verification/1:0`). Находки `automatic_repair` (запись добавила или потеряла не меньше трёх слов) пересинтезируют части, которых касаются произнесённые слова находки по `frame_map`; запас клипа (`margin_frames`) не расширяет выбор частей. Новый мастер собирается из повторных дублей. Распознаются только пересинтезированные части (`audio-verification/1:<круг>:part:<номер>`); распознавание нового мастера составляется без запроса (`audio-fidelity-derived-processing/1`, `audio-derived-recognition/1`): слова и времена неизменённых частей берутся из распознавания прежнего мастера со сдвигом на новую позицию части, слова пересинтезированных частей — из их распознавания. Источники записаны в `sources`. По этому составленному распознаванию строятся находки, страница проверки и замены по находке, поэтому на неизменённых частях не появляется новый шум распознавателя. Повторный запуск находит сделанные пересинтезы по причине и ничего не оплачивает повторно. Если чужой текст остался после последнего круга, этап останавливается с `episode_audio_repair_exhausted`. Итог — `progress.audio_verification` (`episode-audio-verification/3`): проверки, итоговый audit, мастер, число кругов и находки по маршрутам.

## Проверка пользователем, замены и принятие

После `assembled` автоматическая работа закончена, дальше — команды пользователя:

- `review --export-dir DIR` — страница `index.html` с находками итогового распознавания: клип, текст сценария с выделенным местом, распознанное. Находки распознавателя (та же лемма, имя латиницей) свёрнуты отдельно.
- `repair --candidate-id ID [--candidate-id ID …] --export-dir DIR` — запуск команды и есть подтверждение пользователя. Для каждой находки строится замена `/3` по её словам в сценарии, подтверждается, синтезируется с соседним контекстом, локализуется; все замены вклеиваются одним новым мастером (`local_master`). В `progress.audio_repairs` сохраняются тексты замен и `target_check` вклеенных фраз. Повторный `repair` по находкам старого мастера отклоняется: их распознавание относится к другому звуку.
- `accept --reason TEXT --export-dir DIR` — пользователь принимает ровно тот мастер, который слушал: сохраняется `episode-audio-acceptance/1` (актор, мастер, sha256 звука, причина, время), статус становится `accepted`. Повторное принятие того же мастера ничего не меняет; после принятия замены запрещены. В `DIR` пишутся `master.wav`, `script.txt` и `acceptance.json`.

`accepted` для автоматики равнозначен `assembled`: `run`/`resume` ничего не запускают. Это ещё не `ReleaseManifest`: show notes, их проверка, отдельный transcript и AudioQA не созданы.
