# Screenwriter Callback Discipline And Act Planner Follow-Up

## Goal

Reduce semantic repetition in the pipeline without adding corpus-specific rules or new LLM passes.

The current bottleneck is no longer basic planning correctness. The remaining problem is that:

- `act_planner` still allows callback-only ending scenes whose briefs are too close to mechanism recap
- `screenwriter` still treats some callback/reframing scenes as opportunities to explain again
- cross-act continuity is still too weak when different claim IDs express the same proposition core

This plan focuses on general pipeline behavior, not Hong Kong dollar-specific tuning.

## Current Diagnosis

### What is already fixed

- repeated primary claim reuse inside one act is now split deterministically into:
  - `primary_claim_ids`
  - `callback_claim_ids`
- structural callback-only explanation scenes can now fail the act-planner attempt
- callback-only endings now retain bundled evidence after the claim-role split
- writer has local/global continuity memory and no longer depends on full act-contract duplication

### What still fails in practice

1. `screenwriter` does not explicitly know whether the current scene is:
   - introducing new material
   - mixing new material with callback
   - callback-only

2. `screenwriter` still receives `previous_scene` as planning metadata, not as a compact extract of what the listener actually just heard.

3. `act_planner` still allows callback-only endings whose `description` is structurally too close to:
   - mechanism walkthrough
   - recap of the core explanation scene

4. Cross-act repetition remains possible when:
   - Act N established a mechanism as primary
   - Act N+1 uses different claims with the same underlying proposition core

## Design Principles

- No corpus-specific term dictionaries
- No extra LLM pass just to summarize previous scenes
- Prefer deterministic continuity extraction from already-written dialogue
- Prefer structural constraints over keyword-policing
- Keep prompt additions small and targeted

## Phase 1: Make Screenwriter Explicitly Callback-Aware

### Files

- `/Users/yaroslavabramov/side/podgen/backend/app/pipeline/phase6_writing/screenwriter.py`
- `/Users/yaroslavabramov/side/podgen/backend/tests/test_screenwriter_prompt.py`

### Changes

Add explicit scene claim-role context to the writer payload.

For each scene payload, include:

- `primary_claim_ids`
- `callback_claim_ids`
- `scene_claim_mode`

`scene_claim_mode` should be derived deterministically:

- `primary`
  - scene has primary claims and no callback claims
- `callback`
  - scene has callback claims and no primary claims
- `mixed`
  - scene has both primary and callback claims

### Prompt changes

Add a direct rule to `SCREENWRITER_SYSTEM`:

- callback claims are not new exposition material
- callback-only scenes should reference, reframe, contrast, or land a consequence
- callback-only `takeaway` / `summary` / `transition` scenes must not reteach the mechanism from scratch

Make the rule operational:

- if `scene_claim_mode = callback`, the scene should treat prior mechanism as already known
- if `scene_claim_mode = mixed`, explain only the primary part and use callback claims briefly

### Why this matters

Right now writer only infers this distinction indirectly from continuity context. It needs to be told explicitly what kind of scene it is writing.

## Phase 2: Replace Planning-Based Previous Scene Context With Written Scene Continuity

### Files

- `/Users/yaroslavabramov/side/podgen/backend/app/pipeline/phase6_writing/screenwriter.py`
- `/Users/yaroslavabramov/side/podgen/backend/tests/test_screenwriter_prompt.py`

### Changes

Replace or de-emphasize `previous_scene.description` as the main continuity input.

Build a deterministic continuity payload from the actual previously written scene.

Suggested fields:

- `previous_scene_summary`
  - compact extract from the actual previous scene dialogue
  - no new LLM call
- `previous_scene_claim_ids`
  - claim IDs actually used in the previous scene dialogue
- `previous_scene_mechanism_anchors`
  - extracted from previous scene dialogue or the previous scene's actually used claim statements
- `previous_scene_last_line`
  - last spoken line, for rhetorical bridge continuity

### Important implementation note

Do not create a new persistent “summary artifact” generated by an LLM.

Instead, deterministically derive continuity from:

- previous scene `dialogue_json`
- actual `claim_ids` used in that dialogue
- short statement slices from `claim_lookup`
- extracted anchors

### Why this matters

The current `previous_scene` is still based on the beat-sheet description. That tells writer what the previous scene was supposed to do, not what the listener actually heard.

## Phase 3: Tighten Callback-Only Ending Discipline In Act Planner

### Files

- `/Users/yaroslavabramov/side/podgen/backend/app/pipeline/phase5_planning/act_planner.py`
- `/Users/yaroslavabramov/side/podgen/backend/tests/test_act_planner_prompt.py`

### Prompt changes

Strengthen the ending rule in `ACT_PLANNER_SYSTEM`:

- if a `takeaway`, `summary`, or `transition` scene is callback-only, it must focus on:
  - implication
  - cost
  - contrast
  - bridge
- it must not function as a mechanism walkthrough

### Structural constraints

Do not implement keyword-matching validators.

Instead, use language-agnostic structural constraints for callback-only endings:

- callback-only ending scenes should usually have at most `1-2` callback claims
- callback-only ending `description` should stay short relative to normal explanation scenes
- callback-only ending scenes should remain advisory if they are compact and properly shaped
- callback-only ending scenes should fail the quality gate if they become oversized recap blocks

### Why this matters

This is the narrowest place where we can discourage “one more explanation disguised as a takeaway” without adding brittle prose heuristics.

## Phase 4: Cross-Act Follow-Up For Act Planner

### Files

- `/Users/yaroslavabramov/side/podgen/backend/app/pipeline/phase5_planning/act_planner.py`
- `/Users/yaroslavabramov/side/podgen/backend/tests/test_act_planner_prompt.py`

### Changes

Before planning act `N`, provide a compact summary of what previous acts already established as primary material.

Do not use raw `mechanism_anchors` as the main planner memory.

Instead, pass:

- `prior_acts_primary_claims`
  - only claims that served as `primary_claim_ids` in previous acts
  - compact form:
    - `id`
    - short `statement`
    - `act_number`

### Prompt rule

Tell act planner:

- these primary points are already established in earlier acts
- do not assign materially overlapping points as new primary explanations unless the act is adding a genuinely new layer
- if prior material must recur, prefer callback framing

### Why this matters

This is the right upstream follow-up to cases like:

- previous act established the mechanism
- next act returns to the same proposition core through different claim IDs

This is more robust than trying to drive act planning from raw anchor strings.

## What Not To Add

Do not add:

- corpus-specific term dictionaries
- keyword validators for “bad explanation prose”
- a separate LLM summary step for previous-scene continuity
- another large `do_not_repeat` payload blob if the same information already exists in:
  - `callback_claim_ids`
  - previous-scene continuity
  - prior primary claims

## Implementation Order

### P0

1. `screenwriter`: `scene_claim_mode` + `callback_claim_ids`
2. `screenwriter`: previous-scene continuity from actual written dialogue

### P1

3. `act_planner`: stronger callback-only ending prompt rule
4. `act_planner`: structural limits for callback-only endings

### P2

5. `act_planner`: `prior_acts_primary_claims` cross-act continuity

## Tests To Add

### Screenwriter

- payload includes `scene_claim_mode` and `callback_claim_ids`
- callback-only scene prompt contains no primary claims
- previous scene continuity prefers actual written dialogue over beat-sheet description
- previous scene continuity carries:
  - previous scene claim IDs
  - previous scene mechanism anchors
  - previous scene last line
- callback-only writer payload still allows bridge/consequence writing without empty evidence context

### Act Planner

- callback-only ending with compact description remains advisory
- callback-only ending with oversized recap-style description fails quality gate
- prior-act primary claims are included in prompt payload for later acts
- later act payload does not include raw anchor bag as the main cross-act planner memory
- deferred P2 test:
  - a later-act scene whose claims are semantically close to prior-act primary material should be pushed toward callback framing rather than a fresh primary explanation

## Success Criteria

The next full run should show:

- fewer writer-level mechanism re-explanations in callback-only endings
- less duplication between:
  - Act 2 mechanism scene and Act 2 takeaway
  - Act 3 establishment scene and Act 3 takeaway
- better separation between:
  - “this is new”
  - “this is callback/reframing”
- no new corpus-specific heuristics added to runtime logic

## Expected Residual Risk

Even after these changes, some semantic overlap will remain when different claims are themselves too close in meaning.

That is acceptable.

The goal of this phase is not perfect proposition-core dedupe everywhere. The goal is to stop the pipeline from:

- treating callback scenes as fresh explanation scenes
- resetting continuity at every scene boundary
- promoting prior-act mechanism material back into new primary exposition by default
